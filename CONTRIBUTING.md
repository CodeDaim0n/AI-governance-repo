# Contributing

Thank you for considering a contribution. Start with the [developer guide](docs/development/contributing.md) and [architecture decisions](docs/decisions/README.md).

A useful change explains the concrete problem, resulting behavior, test evidence and remaining limitations. Preserve the distinction between a proposed control, implemented code, a passing contract test, native integration and production observation.

- Keep changes scoped and include meaningful failure/negative tests.
- Never add credentials, customer data, private traces or unreviewed generated dependencies.
- Follow the project's [security reporting guidance](SECURITY.md).
- Do not enable recurring bots, external notifications or automatic deployment as an incidental change.
- Contributions use the project's MIT license; integrated dependencies retain their own licenses.
